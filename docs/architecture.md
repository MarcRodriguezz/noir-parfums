# Architecture

The site is static HTML generated by Astro, with no server, database or client framework. The HTML holds all the content. JavaScript adds navigation and animation, so the page stays complete if a script fails.

## Directory layout

```
src/
  assets/images/    Source photographs; Astro generates the variants at build time
  components/
    scenes/         One scene per file, with no animation logic
    ui/             Photo.astro, a <Picture> wrapper with the image policy
  data/product.ts   Product data and navigation
  layouts/          Metadata and boot script
  lib/              Pure functions, covered by unit tests
  pages/            index, reserved, 404
  scripts/
    main.ts         Entry point
    navigation.ts   Mobile menu, active link and header backdrop
    landing.ts      In-page link transitions
    motion/         One module per scene, plus scheduling and particles
  styles/
    tokens.css      Design tokens
    base.css        HTML elements
    components.css  Header, footer, buttons and links
    scenes.css      Scene layout and animation modes
```

## Responsibilities

| Concern      | Location                 | Rule                                          |
| ------------ | ------------------------ | --------------------------------------------- |
| Content      | `src/data/product.ts`    | Product data is not repeated in components    |
| Presentation | `components/`, `styles/` | Works without JavaScript                      |
| Pure logic   | `src/lib/`               | No DOM access                                 |
| Animation    | `src/scripts/motion/`    | Reaches the markup through `data-` attributes |

## Boot sequence

1. An inline script adds the `js` class to `<html>` before first paint, so animation styles apply with no layout shift.
2. The same script starts a 5 second timer. If `main.ts` has not started by then, it removes `js` and the page falls back to the static layout.
3. `main.ts` sets `js-ready` and starts navigation.
4. Unless reduced motion is requested, `motion/index.ts` is imported as a separate module.
5. `startMotion` registers the motion profiles. The first scene starts immediately, and the rest is set up during browser idle periods.

## In-page navigation

`landing.ts` handles links to any `[data-scene]` section. It updates the URL and moves to the scene's landing position, which is one of:

- the scroll position of the scene's `landing` timeline label, for held scenes
- the top of the scene's `[data-landing]` element, minus the header height, for everything else

Without JavaScript, the links are ordinary anchors. See [link transitions](animation.md#link-transitions).

## Reservation form

The reservation is a `GET` form that targets `/reserved/`, with the size as its only parameter. It works without JavaScript and stores nothing. `findEdition` validates the parameter against the known sizes, and the result is written with `textContent`.
